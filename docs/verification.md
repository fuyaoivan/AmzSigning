## 故障定位

原有 LaunchAgent 按计划执行，到期项目也产生了六小时重试记录。失败发生在 Xcode 工具启动阶段：更新后未确认许可，`xcrun` 返回状态码 69，构建和安装均未开始。原设置页只依据调度注册结果显示就绪，不能反映工具链阻塞。

许可处理后，进一步确认 Xcode 27 的设备协议变化：列表中的物理设备可能缺少真机类型和开发者模式字段，完整状态位于设备详情；新版 `properties` 结构及开发者模式枚举需要独立解析。旧版直接过滤缺失字段会忽略有效设备。Xcode 27 同时移除了 `xcdevice enable`，不能继续将该命令作为设备准备步骤。

更新后的第一次设备服务访问另遇到开发镜像无法挂载，底层错误明确为设备锁定。使用者解锁后，设备信息及文件查询恢复。该错误归类为需要解锁，与缺少设备支持组件分别处理。

## Release 安装与真实续签

Release 编译、矢量图标打包及 `codesign --verify --deep --strict` 均通过。安装程序完整替换源码目录中的应用，保留原有运行配置，并删除构建和打包缓存。

在 Xcode 图形界面退出后，通过安装后的 Helper 对两个已管理原生项目执行真实 USB 覆盖安装。两项均获得新开发签名，安装返回成功，且安装后重新查询到相同 Bundle ID 的 App。设备绑定和签名身份保持不变；上次成功时间依据安装回执更新，重试时间清除，下次续签恢复为成功时间加六天。

安装前后分别枚举两个 App 的数据容器，原有普通文件中分别有 418 个和 24 个保持路径、大小及修改时间一致。所有目录项增删和元数据变化均位于系统 `Library/SplashBoard/Snapshots/`；其他目录项未发现差异。此项属于目录及元数据比较，没有读取业务文件内容或执行内容校验和。

构建目录和描述文件恢复区在两项续签完成后均为空。代码及实机执行未调用卸载或删除设备数据接口。
