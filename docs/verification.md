## 故障证据与处理范围

LaunchAgent 已加载，存在到期执行和六小时重试记录；此前一项原生项目也已取得无线安装成功回执。系统与 Xcode 版本和上次验证一致，许可与首次启动检查通过，没有证据表明此次故障由新的系统升级或调度失效引起。

失败分为以下几类：

- 登录服务连接失败：构建错误包含 `Underlying error code -1004`。Foundation 将该值定义为 `NSURLErrorCannotConnectToHost`，不能单独作为凭据失效依据。旧版因匹配到登录失败文字而提示重新登录，现改为网络故障及六小时重试。
- 账号缺失：后续构建明确返回 `No Accounts`，Xcode 的 Apple Accounts 界面也没有已登录账号。使用者完成登录后，命令行签名恢复。现有证据不足以判断此前账号记录或凭据失效的具体来源；本工具没有账号删除、钥匙串清理或凭据写入接口。
- 设备暂不可用：部分重试返回 CoreDevice 错误 4016，未建立所需开发连接。此类错误按连接失败处理，不自动改变设备信任或配对关系。
- 提醒未送出：系统通知授权为拒绝；旧版在进程启动前记录 `attempted`，无法区分拒绝授权、提交失败与成功。新版记录实际提交结果，并保留有时间间隔的失败重试。

## Release 与真实 Wi-Fi 续签

Release 编译、矢量图标打包及 `codesign --verify --deep --strict` 均通过。安装程序完整替换源码目录中的应用，保留运行配置，并清理构建及打包输出。

Xcode 图形界面退出后，安装后的 Helper 使用 `retry` 对两个失败项目执行真实 Wi-Fi 覆盖安装。两项均获得新开发签名，安装返回成功，且安装后再次查询到原 Bundle ID 的 App。设备绑定、管理标识、Team、Bundle ID 与启用状态均与执行前一致。成功时间依据安装回执更新，重试期限清除，下次续签恢复为成功时间加六天。

安装前后分别枚举数据容器：项目 A 为 624 个目录项，项目 B 为 55 个目录项，数量均未改变；分别有 416 个和 24 个原有普通文件保持路径、大小及修改时间一致。所有目录项差异均位于系统 `Library/SplashBoard/`，其他目录项没有变化。验证没有读取业务文件内容或执行内容校验和。

签名构建结束后，专用构建目录与描述文件恢复区均为空。代码及本次执行没有调用卸载或设备数据删除接口。
