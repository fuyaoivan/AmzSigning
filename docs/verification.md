## 故障证据

LaunchAgent 已加载，存在自动执行及六小时重试记录。两个已管理项目在此前周期均有真实无线安装成功回执。当前系统、Xcode 版本和工具选择指纹未发生变化，许可与初始化检查通过；没有证据将本次失败归因于新的系统升级或定时任务未触发。

构建明确返回 `No Accounts: Add a new account in Accounts settings`。同时，Xcode 的 Apple Accounts 界面显示未登录，账号列表为空。使用者重新登录后，在关闭 Xcode 图形界面的条件下，两项命令行签名与无线覆盖安装均成功。续签前后账号数量保持为一，工具未修改账号配置或钥匙串。

现有证据只能确定账号缺失阻止了签名，不能确定此前账号被移除的操作者或进程。本次未通过删除账号配置、重建钥匙串或接受系统协议尝试恢复登录。应用不能代替使用者完成 Apple 身份验证，也不能保证外部账号状态永久有效。

部分失败记录另含 CoreDevice 错误 4016，按设备连接暂不可用处理。一条目标等待超时错误的缩进续行明确要求解锁设备，但旧诊断提取逻辑只保留错误首行，导致解锁原因丢失。修复后保留 Xcode 工具错误的连续上下文，并排除无关账号日志及编译器源码摘录。

本次通知授权已开放，旧运行状态包含系统接受提交的回执，不属于此前的通知授权拒绝问题。提交回执不表示使用者已经阅读通知。

## Release 与实机安装

Release 编译、矢量图标打包和 `codesign --verify --deep --strict` 通过。安装程序完整替换本地应用，保留配置并删除构建及打包目录。

安装后的 Helper 使用 `retry` 对两个失败项目完成真实 Wi-Fi 覆盖安装。两项均生成新的开发签名，安装接口返回成功，随后再次查询到目标 App。项目管理标识、Bundle ID、Team、设备绑定及启用状态保持一致。成功时间按安装回执更新，失败等待期限清除，下一周期为各自成功时间加六天。签名到期日期为 2026-10-22。

## 文件生命周期与空闲运行

命令级独立目录统一承载捕获输出、`TMPDIR` 和 Xcode 结果包。真实工程 `-list`、构建设置查询及签名构建均接受显式 `-resultBundlePath`。另使用不存在的临时工程触发退出码 66，确认失败结果包生成在指定目录内并随验证目录删除。

超时采用 Swift `ContinuousClock`，睡眠计入经过时间，唤醒后可终止已超期任务。本次验证了常规超时与进程组终止，没有主动休眠测试机器。时钟语义见 [Apple ContinuousClock 文档](https://developer.apple.com/documentation/swift/continuousclock)。

续签后专用构建目录、命令临时目录及描述文件恢复区均为空。连续三次空闲 `tick` 耗时 65.14–69.84 ms，状态文件逐字节不变，没有触发扫描或安装。LaunchAgent 最近退出码为 0；关闭设置窗口后，设置进程与 Helper 均退出。
